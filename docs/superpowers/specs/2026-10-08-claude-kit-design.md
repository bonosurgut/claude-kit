# claude-kit — спецификация v1

**Дата:** 2026-10-08
**Статус:** утверждена, реализована в v1
**Репозиторий:** `bonosurgut/claude-kit` (публичный; до явной команды — только локально)

## 1. Зачем

Бесплатный набор для клиентов, которых пользователь учит работать с Claude Code. Клиент ставит
его двумя командами и сразу видит всё нужное: сколько занято контекста, сколько осталось лимитов,
сколько стоит сессия. Когда контекст заполняется, работа одной кнопкой переезжает в **новую**
сессию того же проекта, а старая остаётся доступной.

**Критерий успеха:** клиент-новичок ставит набор → видит шкалы → на 50% получает вопрос → жмёт
«Передать» → в новой сессии видит пересказ работы и пишет «поехали». Старая сессия на месте,
работа закоммичена.

**Происхождение идей.** Идеи (шкалы под полем ввода, вопрос на пороге контекста) подсмотрены
в модах Никиты Велса. Код и тексты пишутся с нуля: его архив без лицензии, а значит, права на
код у автора. Основа скилла — собственный скилл `handoff` пользователя.

## 4. Фичи

### Каталог и установка

- **F-01. Маркетплейс.** `marketplace.json` перечисляет `ctx` и `handoff`. Установка:
  `claude plugin marketplace add bonosurgut/claude-kit`, затем `claude plugin install ctx@claude-kit`
  и `claude plugin install handoff@claude-kit`. `claude plugin validate` зелёный для каталога и
  обоих плагинов.
- **F-02. README на русском.** Что делает каждый плагин, установка, настройки, как выключить,
  требование версии ≥ 2.1.293, раздел «Windows: не проверено вживую» со ссылкой на чек-лист,
  благодарность за идеи.

### ctx — строка под полем ввода (в приложении — над ним)

- **F-03. Шкала контекста.** `▪▪▪▪▪▫▫▫ 62%` — 8 делений, процент из
  `$.session.usage().context.percent`, округлённый до целого. Ниже порога без пометки, от порога
  (процент после округления ≥ порога) — значок 🔴 перед шкалой (цветов в строке состояния нет, см.
  F-07); жёлтой зоны нет. Порог берётся из настроек `ctx` (`redAt`), по умолчанию 50: это то же число
  и то же правило округления, что у порога вопроса handoff (F-15), поэтому 🔴 и вопрос появляются на
  одном и том же проценте. Без данных о контексте — шкала не рисуется.
- **F-04. Лимиты 5 ч и неделя.** `5ч ▪▫▫▫▫▫▫▫ 14%` и `нед ▪▪▪▪▫▫▫▫ 48% · сброс чт 10:00` из
  `rateLimits` (`five_hour`, `seven_day`). Окна без данных **не рисуются** (у API-ключей и
  прокси их нет) — никакого «0%». Время сброса — в локальном часовом поясе, день недели
  по-русски.
- **F-05. Таймер кэша.** `кэш ◷ 3м` — минуты с конца последнего хода главной сессии.
  Срок кэша — настройка (по умолчанию 5 мин). Пока срок не вышел — обычный цвет; вышел —
  тусклый `кэш остыл`. До первого хода не рисуется.
- **F-06. Стоимость.** `$1.84` из `cost` (два знака). Настройка «показывать стоимость»,
  по умолчанию да. Нет `cost` — не рисуется.
- **F-07. Поверхности.** Рисуется в терминале и во вкладке Code приложения. В терминале — строкой
  состояния под полем ввода (проба S-0). В приложении — полосой над полем ввода (`AbovePrompt`,
  приглушённый текст; уступает опросу приложения), а строка состояния там убирается: приложение 2.37+
  ставит строку состояния плагина отдельным рядом под выбором модели, и вернуть её в ряд «Auto / Opus»
  мод не может (живая проба 2026-10-14). Если сессию видит не только приложение (терминал, телефон,
  VS Code), строка состояния остаётся. В полосе строка подписана `ctx` (у полосы своей подписи нет).
  Обновляется после каждого хода и раз в минуту (таймер кэша). Цветов в строке состояния нет,
  поэтому шкала контекста от порога (по умолчанию 50%) помечается значком 🔴 в начале строки;
  значок не может быть ⚠ и в строке нет слова `ctx`, потому что Claude Code сам рисует статус
  плагина как `⚠ <имя плагина>: <текст>` (замечено вживую в 2.1.295, терминал).

### handoff — скилл

- **F-08. Обобщённый скилл.** `skills/handoff/SKILL.md` на основе скилла пользователя: те же
  разделы хендоффа, цепочки `chain_tag`/`seq`, потолок 250 строк, маскировка секретов.
  Убрано всё личное: `HARNESS-CHANGES-LOG.md`, Kimi Code, `measure-cost.py`, замеры стоимости,
  ссылки на `~/.claude/skills/...` (пути скриптов — от строки «Base directory for this skill: …», которую Claude Code
  печатает в начале текста скилла при его загрузке; проверено вживую. Поэтому не `${CLAUDE_PLUGIN_ROOT}`).
- **F-09. Кроссплатформенные скрипты.** `gather.sh` переписан на Python (`gather.py`), вывод
  тех же ключей (`ROOT`, `NOT_GIT`, `BRANCH`, `HANDOFF_DIR`, `FRESH_STANDALONE_TAG`, …).
  `index.py` переносится как есть. Все скрипты запускаются `python3 -I` (Mac) / `py -3 -I`
  (Windows) — в SKILL.md указана команда для обеих систем. Пути с пробелами и кириллицей,
  UTF-8 явно.
- **F-10. Папка хендоффов.** Первая существующая из
  `docs/superpowers/handoffs`, `plans/handoffs`, `docs/handoffs`, `.claude/handoffs`; если нет
  ни одной — `docs/superpowers/handoffs`, если есть `docs/superpowers`, иначе `docs/handoffs`.
  **Без Git** — `<папка, где началась сессия>/docs/handoffs`, без вопроса пользователю (в автоматическом
  режиме спрашивать некого) и без коммита. Новая папка по умолчанию — НЕ `.claude/…`: запись
  в `.claude/` Claude Code всегда подтверждает вручную, и автоматическая передача без человека
  встала бы (решение пользователя 2026-10-09, ревью задачи 6). Уже существующая
  `.claude/handoffs` по-прежнему подхватывается — ради продолжения старых цепочек.
  Папка проекта — корень сессии, который отдаёт движок (`$.session.root()`): папка, в которой
  сессия началась; `cd` оболочки во время работы его не двигает (двигают `/cd`, смена папки
  хостом и перенос в рабочее дерево). В автоматическом режиме скилл ищет цепочку и состояние Git
  в папке пути, который передал мод (`gather.py --handoff-dir`), а не в текущей папке оболочки
  (живая ошибка 2026-10-11…13: сессия открыта в папке без Git, внутри которой лежат отдельные
  репозитории, агент сделал `cd` в один из них, и хендофф лёг туда).
- **F-11. Автоматический режим.** Аргумент `auto <путь>` (его передаёт мод): скилл пишет
  хендофф **ровно в `<путь>`**, дописывает `INDEX.md`, молча коммитит (F-12) и **ничего не
  спрашивает**. Вывод заканчивается строкой `HANDOFF_DONE: <путь>`.
- **F-12. Молчаливый коммит с фильтром.** `commit.py` коммитит хендофф, `INDEX.md` и файлы,
  изменённые в этой сессии (список передаёт модель; новые неотслеживаемые файлы — только если
  модель назвала их как созданные в сессии). **Никогда** не коммитит файлы, похожие на секреты:
  `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `id_ed25519*`, `*credentials*`, `*secret*`,
  `*.keystore`, `*.env`, `id_ecdsa*`, `id_dsa*` — даже если их нет в `.gitignore`. Отсечённые и пропущенные файлы печатаются
  (`SKIPPED_SECRET: …`, `SKIPPED_UNRELATED: …`). Ошибка коммита (нет Git, хук отклонил,
  конфликт) не роняет передачу: печатается `COMMIT_FAILED: <причина>`, причина дописывается
  в хендофф.
- **F-13. Ручной режим.** `/handoff:handoff` без мода (старая версия Claude Code или мод
  выключен): то же, что F-11, но путь скилл выбирает сам (имя
  `HANDOFF_{chain_tag}_{slug}_{YYYY-MM-DD}.md`, как в оригинале), а в конце — фраза для вставки в новую сессию (как в оригинале)
  и подсказка, как открыть новую сессию. Вопрос «закрыть сессию?» убран — коммит молча
  (решение пользователя).
- **F-14. Фраза для новой сессии.** Одна для обоих режимов: «Прочитай `<путь>` (seq N, tag) …
  Перескажи в 5–8 строках цель, состояние, что пробовали и не вышло; прочитай только файлы из
  Must-read; скажи, что проверишь первым. Потом жди моего «поехали».»

### handoff — мод-триггер

- **F-15. Вопрос на пороге.** На `session.measure` при контексте ≥ порога (настройка, по
  умолчанию 50) — по округлённому проценту, как в строке ctx (49.5 уже «50%» и уже спрашивает
  при пороге 50) — `$.ui.ask`: «Контекст N%. Передать работу в новую сессию?» (N — тот же
  округлённый процент) → «Передать» / «Не сейчас». «Не сейчас» или закрытый вопрос → следующий
  порог = N + шаг (настройка, по умолчанию 10). Порог снова снижается до исходного только после
  того, как контекст (по тому же округлённому проценту) упал ниже него (защита от повторного
  вопроса сразу после передачи). Не
  спрашивает, если у сессии нет поверхностей (`claude -p`, фоновые сессии) или передача уже идёт.
- **F-16. `/handoff-now`.** Команда запускает передачу сразу, без порога. Повторный вызов во
  время передачи — сообщение «передача уже идёт: <путь>».
- **F-17. Запуск скилла и ожидание.** Мод сам вычисляет путь тем же правилом, что F-10
  (`<HANDOFF_DIR>/HANDOFF_auto_<YYYY-MM-DD-HHMMSS>.md`), запускает `/handoff:handoff auto <путь>`
  и ждёт, пока по этому пути появится файл с временем изменения не раньше начала передачи
  (проверка в конце каждого хода). Тайм-аут 15 мин или ход записи закончился без файла →
  отмена: тост «Хендофф не записан — ничего не закрыто» (ход записи закончился без файла) или
  «Хендофф не дождались — ничего не закрыто» (тайм-аут), старая сессия работает дальше.
- **F-18. Новая сессия — терминал Mac.** Новое окно Терминала: временный файл `.command`
  (`cd <корень проекта>` и `claude '<фраза F-14>'`), открытый через `open`. Успех = `open`
  завершился с кодом 0. (Не `osascript` → Terminal: управление Терминалом из скрипта требует
  отдельного разрешения macOS «Автоматизация», а кавычки AppleScript ломаются на кириллице.)
- **F-19. Новая сессия — терминал Windows.** `wt -d <корень> claude "<фраза>"`, если есть
  Windows Terminal; иначе `cmd /c start "" /D <корень> <claude> "<фраза>"` (без вложенного `cmd /k`: он
  срезает кавычки, если в пути к claude есть пробел). Путь к хендоффу с символами
  `"&|<>^%;` или с переводом строки — сразу запасной путь А (cmd или Windows Terminal исказили бы путь). **Не проверено вживую** — помечается в матрице и README.
- **F-20. Новая сессия — приложение.** (1) фоновый запуск
  `claude -p --session-id <новый uuid> --permission-mode default` с фразой F-14 в stdin, в корне
  проекта: новая сессия читает хендофф и пишет пересказ (режим `default`: в `-p` правки некому
  разрешить, поэтому они отклоняются; режим `plan` оставлял лишний файл в `~/.claude/plans/`); (2) `claude://resume?session=<uuid>`
  (`open` на Mac, `rundll32 url.dll,FileProtocolHandler` на Windows); (3) ожидание записи
  приложения о чате до 60 с (на Mac — файл в `~/Library/Application Support/Claude/
  claude-code-sessions/…`; на Windows путь неизвестен → ожидание не проверяется, сразу
  запасной путь А **в дополнение** к ссылке). Не появился → запасной путь А.
  Режим нового чата после «поехали» должен разрешать правки — проверяется пробой S-0.
- **F-21. Запасной путь А.** Фраза F-14 — в буфер обмена (`$.ui` clipboard), тост «Новая сессия
  не открылась сама (причина). Фраза скопирована: …»; конец зависит от того, где идёт сессия:
  - приложение (среди поверхностей есть `desktop`): «…нажми ⌘N (Windows: Ctrl+N) и вставь»; в тосте
    стоит клавиша только своей ОС;
  - только терминал: «…открой новое окно терминала, запусти claude в папке проекта и вставь»;
  - всё остальное (VS Code, телефон рядом с терминалом, поверхностей нет): «…открой новую сессию
    Claude Code в папке проекта и вставь».

  ⌘N годится только приложению: в Терминале он по умолчанию открывает новое окно с обычной оболочкой,
  в VS Code — новый пустой файл (находка финального ревью). Буфер недоступен → фраза целиком в тосте и отдельной строкой в
  журнале сессии (`$.ui.log`, история чата), потому что тост висит несколько секунд; тот же конец
  подсказки, но с большой буквы и с двоеточием перед фразой («Нажми ⌘N и вставь: …»).
- **F-22. Закрытие старой сессии — последним.** Только после успеха F-18/F-19/F-20
  (не после запасного пути А): в терминале — `/exit` через `$.command.run`; окно остаётся,
  сессия доступна в `claude --resume`. В приложении старый чат остаётся в списке как есть
  (не архивируется). При запасном пути А старая сессия **не закрывается**.
- **F-23. Переживает перезапуск.** Состояние передачи (метка, путь, время начала) — в
  `$.store` под id сессии. Незавершённая передача доводится или отменяется:
  - в терминале (`isInteractive` истинно) — на `session.start`;
  - в приложении (оно идёт через SDK, `isInteractive` ложно) — на первом `session.attach`, а если клиент
    к концу старта уже подключён (мод перезапустили в открытом чате) — в конце `session.start`;
    неинтерактивная сессия, к которой никто не подключился (голый `claude -p`), метку не трогает;
  - метка не старше 15 минут: файл есть → шаг запуска новой сессии (F-18…F-20); файла нет → ждём, пока
    не выйдут 15 минут, потом тост «не дождались». Метка старше 15 минут окно не запускает никогда:
    файл свежий → запасной путь А (причина «передача прервалась»), файла нет → тост «не дождались».

  Записи старше 30 дней удаляются на старте любой сессии.
- **F-24. Настройки.** Через `userConfig` плагинов: `handoff` — порог (50), шаг (10);
  `ctx` — порог красного (50), срок кэша в минутах (5), показывать стоимость (да).

## 5. Сбои (сводка)

| Сбой | Реакция | Фича |
|---|---|---|
| Хендофф не записан / тайм-аут | отмена, тост, старая сессия работает | F-17 |
| Коммит не прошёл | передача продолжается, причина в выводе и хендоффе | F-12 |
| Секреты среди изменённых | не коммитятся, перечислены | F-12 |
| Окно терминала не открылось | путь А, старая не закрывается | F-18, F-19, F-21, F-22 |
| Чат приложения не появился за 60 с | путь А | F-20, F-21 |
| Фоновый запуск упал | причина в тосте, путь А | F-20, F-21 |
| Перезапуск посреди передачи | довести или отменить | F-23 |
| Старая версия Claude Code | работает только скилл вручную | F-13 |

Правило: **ни один сбой не молчит** и **старая сессия закрывается последней**.
