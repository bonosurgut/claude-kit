# Ручная проверка на Windows

На Windows набор вживую не проверялся: у автора нет такого компьютера. Этот список нужен, чтобы пройти его руками и честно записать, что работает, а что нет. Автоматические тесты проверяют только то, какие команды будут запущены, но не то, что реально происходит на экране.

Для каждого пункта ниже написано, что сделать и что должно получиться. Результат запишите в таблицу в конце файла и пришлите автору вместе с версией Windows и версией Claude Code (`claude --version`).

## 0. Подготовка

- Windows 10 или 11, терминал PowerShell (или Windows Terminal с PowerShell).
- Claude Code версии 2.1.293 или новее: `claude --version`.
- Git: `git --version` печатает версию.
- Тестовый проект под Git хотя бы с одним коммитом. Если у вас такого нет, создайте:

```
mkdir claude-kit-check
```

```
cd claude-kit-check
```

```
git init
```

```
echo test > README.md
```

```
git add README.md
```

```
git commit -m "init"
```

Если `git commit` просит указать имя и почту, укажите их (подсказка есть в самой ошибке) и повторите.

Секретов в тестовом проекте не держите: для пункта 11 понадобится файл-пустышка.

## 1. Установка

Выполните по очереди:

```
claude plugin marketplace add bonosurgut/claude-kit
```

```
claude plugin install ctx@claude-kit
```

```
claude plugin install handoff@claude-kit
```

```
claude plugin list
```

**Ожидается:** каждая из трёх первых команд заканчивается без ошибки. В списке есть `ctx@claude-kit` и `handoff@claude-kit` со статусом «enabled».

## 2. Python

```
py -3 --version
```

**Ожидается:** `Python 3.x.y`. Если команда не найдена, проверьте ещё `python --version`; скилл умеет пользоваться и тем, и другим. Если не находится ни `py -3`, ни `python`, запишите это: скилл тогда переключится на запасной путь через Git, и это нужно отметить отдельно.

## 3. Строка под полем ввода и значок 🔴

1. В папке тестового проекта запустите `claude` (в Windows Terminal) и отправьте любое короткое сообщение, например «привет».
2. Откройте настройки плагина `ctx`: `/plugin configure ctx@claude-kit`. В поле «Предупреждение 🔴 с, %» поставьте `1`. Откройте новую сессию в той же папке и снова отправьте сообщение.

**Ожидается:**

- под полем ввода есть строка вида `⚠ ctx: ▪▫▫▫▫▫▫▫ 9%   кэш ◷ 0м` (процент и набор частей зависят от вашей сессии; `$` и лимиты 5 ч и «нед» могут отсутствовать, если Claude Code их не сообщает). Часть `⚠ ctx:` рисует сам Claude Code, это не тревога;
- после настройки `1` перед шкалой стоит значок 🔴, и он отображается как красный круг, а не как пустой квадрат или знак вопроса. Если вы видите квадрат, запишите, какое именно окно используется (Windows Terminal или старая консоль).

После пункта верните значение: поставьте в «Предупреждение 🔴 с, %» снова `50`.

## 4. `/handoff-now` в Windows Terminal

1. В Windows Terminal откройте папку тестового проекта и запустите `claude`.
2. Попросите: «Создай файл proba.txt с одной строкой "привет"». Согласитесь, если Claude спросит разрешение.
3. Наберите `/handoff-now`.

**Ожидается:**

- Claude не должен спрашивать разрешение на запуск скриптов хендоффа (если спросил, запишите, на какую именно команду); в чате появляется сообщение «Пишу хендофф; потом коммит и новая сессия»;
- в папке проекта появился файл `docs\handoffs\HANDOFF_auto_ГГГГ-ММ-ДД-ЧЧММСС.md` и файл `docs\handoffs\INDEX.md`;
- последний коммит содержит хендофф, `INDEX.md` и `proba.txt`, и больше ничего:

```
git log -1 --name-only
```

- открывается **новое окно** Windows Terminal. В его верхней части Claude Code показывает папку тестового проекта. Claude уже прочитал хендофф и пересказал его в 5–8 строках, а в конце ждёт слова «поехали»;
- в старом окне сессия закрылась (вернулась командная строка), а само окно осталось. `claude --resume` показывает эту сессию в списке.

Напишите в новом окне «поехали» и убедитесь, что Claude продолжает работу.

## 5. То же без Windows Terminal (обычная консоль)

Плагин ищет Windows Terminal командой `where wt`. Если он у вас установлен, чтобы проверить второй путь, его нужно на время «спрятать»: Параметры → Приложения → Дополнительные параметры приложений → Псевдонимы выполнения приложений (в Windows 10: Параметры → Приложения → Приложения и возможности → Управление псевдонимами выполнения приложений) → выключите переключатель у Терминала/`wt.exe`. Проверьте, что `wt` больше не находится:

```
where.exe wt
```

**Ожидается:** команда ничего не находит. Если выключить `wt` не получилось, пропустите пункт и запишите «не проверено».

Повторите пункт 4 (в классической консоли или PowerShell, запущенных не из Windows Terminal).

**Ожидается:** открывается новое окно консоли, в нём работает Claude Code в папке проекта, пересказ хендоффа и ожидание «поехали» те же. Какое именно окно откроется (старая консоль или Windows Terminal), зависит от настройки Windows «Терминал по умолчанию», запишите, что увидели. Потом верните переключатель `wt.exe` на место.

## 7. Путь со спецсимволами `&`, `%`, `^`, `;`

Для таких путей автоматический запуск окна сознательно **не делается**: командная строка Windows исказила бы путь. Вместо этого фраза копируется в буфер обмена.

```
mkdir "$HOME\a&b%c^d;e"
```

```
cd "$HOME\a&b%c^d;e"
```

```
git init
```

```
echo test > README.md
```

```
git add README.md
```

```
git commit -m "init"
```

Запустите `claude` в этой папке и наберите `/handoff-now`.

**Ожидается:**

- новое окно **не** открывается;
- появляется сообщение «Новая сессия не открылась сама (путь содержит символы, которые искажает консоль Windows). Фраза скопирована: открой новое окно терминала, запусти claude в папке проекта и вставь» (про `Ctrl+N` в нём ничего нет: это сообщение для терминала, а `Ctrl+N` называется только в приложении, см. пункт 9);
- в буфере обмена лежит фраза «Прочитай `…HANDOFF_auto_….md` (seq …, …) и продолжи работу…». Вставьте её в Блокнот и убедитесь, что путь в ней целый, с теми самыми `&`, `%`, `^`, `;`;
- старая сессия **не закрыта**: можно отправить ей сообщение и получить ответ.

Если хендофф вообще не записался из-за необычного имени папки (оболочка Claude Code могла споткнуться об `&` или `;` в пути), запишите это: тогда запасной путь не проверен.

## 8. Ручной запуск по подсказке из пункта 7

После пункта 7 сделайте то, что просит сообщение: откройте новое окно или вкладку Windows Terminal, перейдите в папку тестового проекта, запустите `claude` и вставьте фразу из буфера обмена.

**Записать:** чем удалось вставить (`Ctrl+V`, `Ctrl+Shift+V`, правая кнопка мыши), запустилась ли новая сессия, пересказала ли она хендофф и ждёт ли «поехали».

## 9. Приложение Claude (вкладка Code)

1. Откройте тестовый проект в приложении Claude, вкладка Code, и пошлите любое сообщение.
2. Наберите `/handoff-now`.

**Ожидается:**

- команда `/handoff-now` есть и отвечает «Пишу хендофф; потом коммит и новая сессия»;
- хендофф записан и закоммичен, как в пункте 4;
- на Windows проверить, что новый чат появился, плагин не может. Поэтому, если фоновый запуск и открытие ссылки прошли, появится сообщение «Новая сессия не открылась сама (Windows: проверить появление чата нельзя). Фраза скопирована: нажми Ctrl+N и вставь», **даже если чат открылся сам**. Если же в сообщении другая причина («фоновый запуск: …», «не удалось открыть ссылку на чат»), запишите её;
- **Записать:** появился ли новый чат сам (после запуска ссылки `claude://…`)? Если да, прочитал ли он хендофф и ждёт ли «поехали»?
- Если нет: сработал ли `Ctrl+N` + вставка фразы из буфера в приложении?
- старый чат остался в списке и работает (не закрыт, не архивирован).

## 10. Поведение старой сессии

Собирает наблюдения из пунктов 4, 5, 7 и 9; отдельных действий не требуется. Должно быть так:

- запуск нового окна удался (пункты 4, 5, 6) в терминале: старая сессия закрылась, окно осталось, сессия видна в `claude --resume`;
- запуск не удался или выбран запасной путь с буфером обмена (пункты 7, 9): старая сессия **не** закрылась;
- в приложении старый чат всегда остаётся в списке.

Если где-то произошло иначе, запишите, где именно.

## 11. Файл-пустышка `.env` не коммитится

1. В тестовом проекте проверьте, что `.env` не указан в `.gitignore`. Лучше, чтобы `.gitignore` не было вовсе.
2. Запустите `claude` и попросите: «Создай файл .env с одной строкой TEST_KEY=abc и ещё файл notes.txt с одной строкой "заметка"». Используйте только выдуманное значение, настоящий ключ не кладите.
3. Наберите `/handoff-now`.

**Ожидается:**

- последний коммит содержит `notes.txt`, хендофф и `INDEX.md`, но **не** содержит `.env`:

```
git log -1 --name-only
```

- `.env` остался в папке не закоммиченным:

```
git status --short
```

В выводе есть строка `?? .env`.

- в отчёте Claude в старом окне есть строка `SKIPPED_SECRET: .env`.

## Если новое окно мелькнуло и сразу закрылось

На Windows без Windows Terminal новое окно открывается командой, которая закрывает его сразу, если `claude` не смог запуститься (например, из-за неверного пути). Ошибки вы не увидите. Откройте консоль, перейдите в папку проекта и запустите `claude` руками, чтобы увидеть сообщение об ошибке. Пришлите его автору.
