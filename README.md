# claude-kit

Бесплатный набор из двух плагинов для Claude Code. Плагин — это дополнение, которое ставится в Claude Code отдельной командой и расширяет его возможности.

## Что это

- **`ctx`** — строка со шкалами (в терминале — под полем ввода, во вкладке Code приложения Claude — над ним): сколько занято контекста (это «память» текущего разговора с Claude), какая доля лимитов за 5 часов и за неделю уже использована и когда эти лимиты сбросятся (если Claude Code сообщает время), сколько минут прошло с последнего ответа Claude (пока кэш «тёплый», следующий ответ обычно дешевле) и, если включить настройку, сколько стоит сессия по оценке Claude Code. Слова в строке по умолчанию русские, их можно переключить на английские (настройка «Язык строк»). Во вкладке Code приложения есть ещё две вещи: короткое имя папки, где идёт сессия (в нижнем ряду, слева от выбора модели), и строка про субагентов (помощников, которых запускает Claude): сколько работает, сколько закончило и сколько упало.
- **`handoff`** («передача смены») — когда контекст заполняется, работа одной кнопкой переезжает в **новую** сессию того же проекта. Старая сессия остаётся на месте, работа записана в файл и (если в проекте есть Git) сохранена коммитом.

Так выглядит строка `ctx` в терминале:

```
⚠ ctx: ▪▪▪▪▫▫▫▫ 49%  5ч ▪▪▪▪▪▪▫▫ 71% ↻2ч14м  нед ▪▪▪▪▪▫▫▫ 61% ↻вс 10:00  кэш 2м
```

`⚠ ctx:` в начале — это подпись самого Claude Code (он так подписывает строку любого плагина в терминале). Тревогой этот значок не является. Наша строка начинается с первого квадратика. Тревога у нас — значок 🔴 (о нём ниже).

Та же строка с английскими словами (так её показывает настройка `lang = en`, о ней ниже):

```
⚠ ctx: ▪▪▪▪▫▫▫▫ 49%  5h ▪▪▪▪▪▪▫▫ 71% ↻2h14m  wk ▪▪▪▪▪▫▫▫ 61% ↻Sun 10:00  cache 2m
```

В этих примерах суммы `$` нет: по умолчанию она выключена (см. «Стоимость» ниже).

Вживую на Mac (Claude Code 2.1.295) проверены: строка под полем ввода в терминале и над полем ввода во вкладке Code приложения Claude (приложение 2.37337), значок 🔴 (терминал), вопрос на пороге (терминал; ответ своим текстом — в приложении), ручной запуск `/handoff:handoff` (терминал) и передача по команде `/handoff-now` (терминал и приложение). Только автоматическими тестами проверены запасной путь с буфером обмена и доводка передачи после перезапуска. Папка сессии слева от модели и строка субагентов (ctx 0.2.0) проверены вживую в приложении 3.1623.4 с Claude Code 2.1.308, в том числе после `/clear`. Строка ctx 0.3.0 (плотный вид, остаток до сброса, английские слова, смена настроек через `/plugin`) проверена вживую в терминале (Claude Code 2.1.309) и во вкладке Code приложения 3.1623.4 (его собственный движок — Claude Code 2.1.308); сумма `$` — только в терминале. На Windows не проверялось ничего (см. раздел «Windows»).

## Что нужно

1. **Claude Code версии 2.1.293 или новее** (проверено на 2.1.293–2.1.296; ctx 0.2.0 — на 2.1.308; ctx 0.3.0 — на 2.1.309 в терминале и на 2.1.308 в приложении). Версию показывает команда:

```
claude --version
```

На более старой версии шкалы и вопрос о передаче могут не заработать. Тогда остаётся ручная команда `/handoff:handoff` (см. ниже).

2. **Git** (система сохранения версий файлов). Он нужен, чтобы передача могла сохранить работу коммитом (коммит — снимок изменений в Git). Без Git хендофф всё равно запишется, но коммита не будет.
3. **Python 3** — на нём работают служебные скрипты передачи.
   - Mac: Python обычно уже есть, а если нет, macOS предложит поставить «Xcode Command Line Tools» — согласитесь.
   - Windows: скачайте с python.org и при установке поставьте галочку «Add to PATH» (в окне установщика она называется что-то вроде «Add python.exe to PATH»).
   - Если Python на компьютере нет совсем, скилл переключается на запасной путь: те же шаги через команды Git. Но этих команд (в том числе `git add` и `git commit`) нет в списке заранее разрешённых, поэтому в обычном режиме разрешений Claude Code может спросить у вас разрешение, и автоматическая передача будет ждать вашего щелчка. Так что Python лучше поставить.

## Установка

Откройте обычный терминал (не внутри Claude): на Mac это приложение «Терминал», на Windows — PowerShell или Windows Terminal. Выполните по очереди три команды.

Добавить каталог (список плагинов этого набора):

```
claude plugin marketplace add bonosurgut/claude-kit
```

Поставить `ctx`:

```
claude plugin install ctx@claude-kit
```

Поставить `handoff`:

```
claude plugin install handoff@claude-kit
```

Потом **откройте новую сессию** (закройте текущий `claude` и запустите заново; в приложении откройте новый чат). Проверить, что плагины стоят и включены, можно командой:

```
claude plugin list
```

В списке должны быть `ctx@claude-kit` и `handoff@claude-kit` со статусом «enabled».

Если раньше вы ставили другие моды, которые тоже рисуют строку под полем ввода (например, другой плагин с именем `ctx`), выключите их: набор проверялся без них.

## Как пользоваться

### Шкалы

Строка обновляется после каждого ответа Claude и раз в минуту. В приложении она появляется только после первого ответа Claude в чате.

| Что в строке | Что значит |
|---|---|
| `▪▪▪▪▫▫▫▫ 49%` | Сколько контекста занято. Восемь делений, процент рядом. |
| `5ч ▪▪▪▪▪▪▫▫ 71% ↻2ч14м` | Сколько использовано из лимита за 5 часов и сколько осталось до его сброса. Значок `↻` значит «сброс»: здесь до него 2 часа 14 минут. Когда остаётся меньше часа, показываются только минуты (`↻45м`). Остаток пересчитывается при каждом обновлении строки (после ответа Claude и раз в минуту) и округляется вверх до целой минуты, поэтому за секунды до сброса там `↻1м`, а не ноль. Если Claude Code не сообщил время сброса или оно уже прошло, части `↻…` нет, а сама шкала остаётся. |
| `нед ▪▪▪▪▪▫▫▫ 61% ↻вс 10:00` | Сколько использовано из недельного лимита и когда он сбросится: день недели и время (24-часовое) — в вашем часовом поясе. Если Claude Code не сообщил время сброса, части `↻…` нет. |
| `кэш 2м` | Сколько минут прошло с последнего ответа Claude. Claude Code на несколько минут запоминает уже отправленную часть разговора (это и есть кэш), и пока кэш «тёплый», следующий ответ обычно дешевле. |
| `кэш остыл` | Прошло пять минут или больше: запоминание закончилось. Пять минут — наше предположение по умолчанию. Claude Code может хранить кэш и дольше (например, час); тогда увеличьте «Срок кэша» в настройках. |
| `$0.84` | Сколько стоит эта сессия по оценке Claude Code (считается по прайс-листу API). **По умолчанию не показывается:** на подписке это справочная цифра, а не сумма, которую с вас спишут. Включается в настройках, подробности — в разделе «Стоимость» ниже. |

Если Claude Code не сообщает лимиты (так бывает при работе по API-ключу или через прокси), строки про 5 часов и неделю просто не рисуются. Нулей вместо них не будет. До первого ответа не рисуется кэш. `$` не рисуется, пока настройка стоимости выключена (по умолчанию она выключена), а если включена, то и без данных о стоимости от Claude Code.

Когда контекст дошёл до 50% (порог можно поменять), в начале нашей строки появляется 🔴:

```
⚠ ctx: 🔴 ▪▪▪▪▪▫▫▫ 62%  5ч ▪▫▫▫▫▫▫▫ 14% ↻3ч40м  кэш 2м
```

🔴 относится только к контексту: лимиты его не включают.

### Язык строк

По умолчанию все слова в строках русские. Если удобнее английский, переключите настройку «Язык строк» (`lang`) на `en`. Значений два: `ru` (по умолчанию) и `en`; любое другое плагин читает как `ru`. Чтобы поставить `en`, откройте в Claude Code `/plugin` → Installed → `ctx` → настройки (или `/config`) и выберите `en` в настройке «Язык строк» (значение выбирается из двух вариантов, впечатывать ничего не нужно) (подробнее о настройках и о том, когда они применяются, — в разделе «Настройки» ниже).

Английскими становятся все слова, которые рисует плагин: строка `ctx` (в терминале — под полем ввода, в приложении — в полосе над ним), строка субагентов и её подпись (`агенты` → `subagents`). В полосе приложения обе строки, субагентов и `ctx`, стоят на одном языке. Что как называется:

| По-русски | По-английски `en` |
|---|---|
| `5ч`, `нед` (окна 5 часов и недели) | `5h`, `wk` |
| `↻2ч14м`, `↻45м` (часы и минуты до сброса) | `↻2h14m`, `↻45m` |
| `вс пн вт ср чт пт сб` (день сброса недели) | `Sun Mon Tue Wed Thu Fri Sat` |
| `кэш 2м`, `кэш остыл` | `cache 2m`, `cache cold` |
| `агенты  работают N  готово M  сбой K` | `subagents  running N  ready M  failed K` |

Не меняются: значок `↻`, шкалы, проценты, 🔴, подпись `ctx`, вид суммы (`$0.84`), 24-часовое время (`10:00`) и имя папки сессии в нижнем ряду приложения (в нём нет слов, только путь). Названия и описания самих настроек и сообщения в служебном (отладочном) журнале плагина остаются русскими.

Язык применяется так же, как остальные настройки: сразу после сохранения (подробнее — в разделе «Настройки» ниже).

### Стоимость

Сумма `$` по умолчанию в строке не показывается. Причина: на подписке (Pro, Max) это не настоящие траты, а цена по тарифам API; к тому же сумма делает строку длиннее. Если вы работаете по API-ключу и сумма для вас настоящая, включите настройку «Показывать стоимость» (`showCost`) там же, где язык (раздел «Настройки» ниже). Тогда `$0.84` стоит последней частью строки, одинаково на русском и на английском:

```
⚠ ctx: ▪▪▪▪▫▫▫▫ 49%  5ч ▪▪▪▪▪▪▫▫ 71% ↻2ч14м  кэш 2м  $0.84
```

Если вы включали стоимость сами раньше, она остаётся включённой и после обновления до 0.3.0 (проверено при обновлении с 0.2.0).

**После `/clear` сумма считается заново.** Сумму считает Claude Code, а не плагин: плагин показывает готовую цифру и ничего не пересчитывает. После `/clear` шкала контекста начинается с нуля, и сумма начинает считаться заново: на Claude Code 2.1.309 после `/clear` и одного сообщения она стала меньше прежней.

### Папка и субагенты (только во вкладке Code приложения)

В терминале этого нет: там остаётся одна строка со шкалами под полем ввода, без папки и без строки про субагентов.

**Папка сессии.** В нижнем ряду окна, слева от названия модели, стоит короткое имя папки, где началась сессия: две последние части пути. Перед ним приложение само ставит приглушённое имя плагина, выглядит это примерно так:

```
ctx  CLAUDE/claude-kit
```

Это имя ставит само приложение, и убрать его из плагина нельзя (так вышло при проверке на текущей версии приложения). Как сокращается путь (пример для домашней папки `/Users/anna`; `~` значит «домашняя папка»):

| Папка сессии | Что показано |
|---|---|
| `/Users/anna/Desktop/CLAUDE/claude-kit` | `CLAUDE/claude-kit` |
| `/Users/anna/Desktop` | `~/Desktop` |
| `/Users/anna` | `~` |
| `/srv/app/web` | `app/web` |
| `/tmp` | `/tmp` |
| `C:\Users\anna\proj\web` (Windows, домашняя папка `C:\Users\anna`) | `proj/web` |

Показывается папка, в которой вы открыли сессию (пока вы сами не сменили проект, например командой `/cd`): `cd`, который Claude выполняет по ходу работы, её не двигает. `/clear` папку не меняет. Если домашняя папка неизвестна, показываются две последние части полного пути. Если ту же сессию видит не только приложение (рядом открыт терминал, телефон или VS Code) или неизвестно, где она открыта, папка не показывается: строка состояния одна на все эти места, и она остаётся строкой со шкалами. Переключается сама, без перезапуска, когда приложение подключается к сессии или отключается от неё.

**Строка субагентов.** Субагент — помощник, которого Claude запускает, чтобы часть работы шла параллельно. Строка стоит в полосе над полем ввода, над строкой `ctx`, и появляется после первого субагента сессии:

```
агенты  работают 1  готово 16
ctx     ▪▪▫▫▫▫▫▫ 27%  5ч ▪▫▫▫▫▫▫▫ 14% ↻3ч40м  кэш 2м
```

Подписи `агенты` и `ctx` стоят в одну колонку (ширину колонки задаёт подпись строки субагентов). При `lang = en` строки такие:

```
subagents  running 1  ready 16
ctx        ▪▪▫▫▫▫▫▫ 27%  5h ▪▫▫▫▫▫▫▫ 14% ↻3h40m  cache 2m
```

| Что в строке | Что значит |
|---|---|
| `работают 1` (`running 1`) | Сколько субагентов ещё не закончили (работают или ждут). Число стоит в строке всегда, даже `работают 0`. |
| `готово 16` (`ready 16`) | Сколько закончили успешно. Число стоит в строке всегда, даже `готово 0`. |
| `сбой 2` (`failed 2`) | Сколько упало или было остановлено. Слово появляется, только когда такие агенты есть в счёте, и стоит после `готово`. |

Считаются субагенты на любой глубине, в том числе запущенные другими субагентами. Участники команды агентов (teammates, у каждого есть адрес в команде) в эту строку не входят. Плагин перечитывает список агентов у Claude Code, когда субагент запускается, когда начинается и заканчивается его ход, когда Claude заканчивает свой ответ, и раз в минуту. Закончивший субагент остаётся в `готово` (упавший — в `сбой`), даже когда Claude Code потом убирает его из своего списка. Если Claude написал субагенту после конца работы и тот снова взялся за дело, он снова считается в `работают`. Если прочитать список агентов не получилось, остаются последние известные цифры. `/clear` начинает счёт с нуля: это новый разговор.

### Вопрос на 50%

Когда контекст дошёл до 50% (порог можно поменять), на экране появляется вопрос:

> Контекст 50%. Передать работу в новую сессию?

В окне вопроса две кнопки, **«Передать»** и **«Не сейчас»**, и поле «Other» для своего текста. Отвечайте кнопками: любой текст, который вы впишете в поле (например, «да»), считается ответом «Не сейчас», и передача не начнётся.

- «Передать» запускает передачу (что она делает — ниже).
- «Не сейчас» (а также свой текст в поле или закрытый вопрос) — вопрос повторится, когда контекст вырастет ещё на 10 процентных пунктов (шаг можно поменять) от того значения, при котором вас спросили. Спросили на 50% — повторят на 60%, потом на 70% и так далее.
- Пока идёт передача, вопроса нет. Если передача дошла до открытия новой сессии (или до запасного пути с буфером обмена, см. ниже), вопрос молчит, пока контекст не упадёт ниже порога. Если передачу отменили (сообщения «… — ничего не закрыто», см. ниже), вопрос включается снова и появится так же, как обычно, когда контекст достигнет порога (если контекст уже выше, то при ближайшем обновлении процента).

### Команда `/handoff-now`

Не хотите ждать 50%? Напишите в поле ввода `/handoff-now`, и передача начнётся сразу, при любом проценте контекста. Короткая фраза вроде «ок /handoff-now» или «давай handoff-now» тоже сработает: такую фразу плагин узнаёт сам и в Claude не отправляет (если Claude в этот момент ещё отвечает, плагин попросит отправить её снова после ответа). Длинное сообщение, где команда просто упомянута, уходит в Claude как обычно. В ответ появится сообщение «Пишу хендофф; потом коммит и новая сессия». Если передача уже идёт, вместо этого будет «Передача уже идёт: <путь к файлу>», и вторая не начнётся.

### Что делает «Передать»

Хендофф — это файл-пересказ работы: какая цель, что уже сделано, что пробовали (в том числе неудачное) и что делать дальше.

1. Claude пишет хендофф в папку проекта (по умолчанию `docs/handoffs/`, подробности — в разделе «Известные особенности»).
2. Коммит. В него попадают: сам хендофф, оглавление хендоффов `INDEX.md` и файлы, которые Claude создал или менял в этой сессии. Остальные изменения в папке (например, ваши правки руками) в коммит не попадают. **Файлы с «секретными» именами в коммит не попадают**, даже если их нет в `.gitignore`: `.env*`, `*.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.keystore`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `id_dsa*`, а также файлы со словами `secret` и `credentials` в имени и файлы в папках с такими именами. Проверяется только имя, содержимое файлов не читается: пароль внутри файла с обычным именем эта защита не заметит. Пропущенные файлы Claude перечисляет в своём отчёте. Если коммит не прошёл (нет Git, коммит отклонила проверка и т. п.), передача всё равно идёт дальше, а Claude записывает причину в хендофф.
3. Открывается новая сессия того же проекта:
   - **Терминал (Mac):** новое окно Терминала. Старая сессия закрывается последним шагом, и только после того, как новое окно открылось. Окно с ней остаётся, а саму сессию можно вернуть командой `claude --resume`.
   - **Приложение Claude (вкладка Code):** в списке появляется новый чат с пересказом. Старый чат остаётся в списке как есть, он не закрывается и не архивируется.
4. Новая сессия читает хендофф, пересказывает его в 5–8 строках (цель, состояние, что пробовали и что не вышло), читает только самые нужные файлы, говорит, что проверит первым, и **ждёт, пока вы напишете «поехали»**. После этого она продолжает работу с раздела хендоффа «Where We're Going» (план следующих шагов).

Передача занимает время: сначала Claude пишет хендофф и коммитит, и только потом открывается новая сессия. Если файла хендоффа нет через 15 минут, передача отменяется, а старая сессия работает дальше.

### Если что-то пошло не так

В терминале старая сессия закрывается только после того, как новая успешно открылась (в приложении старый чат не закрывается вообще). Если что-то не получилось, вы увидите сообщение (оно показывается несколько секунд). Вот основные из них:

| Сообщение | Что случилось |
|---|---|
| «Хендофф не запустился (причина) — ничего не закрыто» | Передачу не удалось начать: например, хранилище не приняло служебную метку или не запустился сам скилл `handoff:handoff`. Старая сессия работает. |
| «Хендофф не записан — ничего не закрыто» | Claude закончил ход, а файла хендоффа нет. Старая сессия работает, можно повторить. |
| «Хендофф не дождались — ничего не закрыто» | Файла нет уже 15 минут. Старая сессия работает. |
| «Передача остановлена — ничего не закрыто» | Вы прервали Claude, пока он писал хендофф. |
| «Новая сессия не открылась сама (причина). Фраза скопирована: …» | Окно или чат не открылись. Фраза для новой сессии лежит в буфере обмена, а конец сообщения подсказывает, что делать дальше (три варианта ниже). **Старая сессия при этом не закрывается.** |
| «Новая сессия открыта, но закрыть эту не вышло (причина)» | Новое окно терминала открылось, а команда закрытия старой сессии не сработала. Старая сессия осталась открытой: закройте её сами командой `/exit`. |

Что делать с сообщением про скопированную фразу, смотрите по тому, чем оно заканчивается. Конец зависит от того, где идёт ваша сессия:

- в приложении («…нажми ⌘N и вставь»; на Windows `Ctrl+N`): нажмите это сочетание, чтобы открыть новый чат, и вставьте фразу;
- в терминале («…открой новое окно терминала, запусти claude в папке проекта и вставь»): откройте новое окно или вкладку, запустите в папке проекта `claude` и вставьте фразу;
- в остальных местах, например в расширении для VS Code («…открой новую сессию Claude Code в папке проекта и вставь»): откройте новую сессию Claude Code в папке проекта и вставьте фразу.

Сочетание `⌘N` в сообщении называется только для приложения: в Терминале оно по умолчанию открывает новое окно с обычной оболочкой, а в VS Code — новый пустой файл.

Если буфер обмена недоступен, фраза целиком показывается прямо в сообщении (подсказка в нём та же, но с большой буквы и с двоеточием перед фразой). Кроме того, в этом случае фраза дописывается одной строкой в историю чата: сообщение исчезает через несколько секунд, а запись в истории остаётся.

Новая сессия сама открывается только в терминале и во вкладке Code приложения. В других местах (например, в расширении для VS Code) вы получите это сообщение с фразой в буфере и подсказкой открыть новую сессию самому.

### Ручной режим `/handoff:handoff`

Запасной способ, если вопрос на пороге не появляется (например, на старой версии Claude Code): набрать `/handoff:handoff`. Claude так же пишет хендофф и коммитит без секретов, но новую сессию сам не открывает и старую не закрывает. В конце он печатает фразу, которую вы вставляете в новую сессию сами, и подсказывает, как её открыть. Хендофф ложится туда же, куда положила бы автоматическая передача: в папку, где началась сессия, даже если Claude по ходу работы перешёл во вложенную папку или репозиторий.

## Рекомендуемая настройка: режим Auto

Режим разрешений **Auto** (автоматический) означает: Claude сам решает, какие действия безопасны, и выполняет их, не спрашивая вас каждый раз. Рискованные действия по-прежнему требуют вашего «да». Риск в одну строку: решение «безопасно или нет» принимает сама модель, и она может ошибиться.

Зачем это нужно: пока в настройках не задан режим по умолчанию, приложение открывает любой новый чат в режиме **Manual** (каждое действие спрашивает разрешение), в том числе чат, который открыла передача. Переключить его можно одним щелчком в самом чате, но проще один раз задать режим по умолчанию.

Как включить: вставьте Claude эту фразу.

```
Пропиши в `~/.claude/settings.json` режим разрешений по умолчанию `auto` (`permissions.defaultMode`)
```

Claude попросит разрешение изменить файл настроек, вы соглашаетесь. После этого и обычные новые чаты, и чат, открытый передачей, стартуют в Auto. Сами плагины настройки Claude Code никогда не меняют.

Если Claude Code не принял значение `auto` (режим может быть недоступен на вашем тарифе), оставьте как есть: всё остальное работает, только новый чат в приложении придётся один раз переключить вручную. Чтобы вернуть всё назад, попросите Claude убрать эту настройку.

## Настройки

| Плагин | Настройка | Что делает | По умолчанию |
|---|---|---|---|
| `handoff` | Порог вопроса, % (`threshold`) | С какого процента контекста спросить «Передать?» | 50 |
| `handoff` | Повторить через, % (`step`) | На сколько процентных пунктов должен вырасти контекст после «Не сейчас», чтобы вопрос повторился | 10 |
| `ctx` | Предупреждение 🔴 с, % (`redAt`) | С какого процента контекста перед шкалой ставится 🔴 | 50 |
| `ctx` | Срок кэша, мин (`cacheMinutes`) | Через сколько минут после ответа Claude кэш считается остывшим (по умолчанию считаем, что кэш живёт 5 минут) | 5 |
| `ctx` | Показывать стоимость (`showCost`) | Показывать ли `$` в строке последней частью. На подписке это условная сумма по тарифам API | нет |
| `ctx` | Язык строк (`lang`) | На каком языке плагин рисует слова своих строк: `ru` (по-русски) или `en` (по-английски) | `ru` |

Порог вопроса держится в пределах от 1 до 100, а шаг — целое число не меньше 1; значения вне этих границ программа поправит сама. По умолчанию порог вопроса и порог 🔴 совпадают (оба 50), и оба сравнивают процент, округлённый до целого, то есть тот, что вы видите в строке. Поэтому 🔴 и вопрос появляются на одном и том же проценте (вопроса может не быть, если вы уже ответили «Не сейчас» и он ждёт следующего порога или если передача уже идёт). Если захотите разнести пороги, меняйте каждый отдельно.

Где поменять: в Claude Code откройте `/plugin` → Installed → нужный плагин → настройки. Второй путь — `/config`: настройки обоих плагинов стоят там в общем списке с подписью плагина (например, «Язык строк · ctx» или «Порог вопроса, % · handoff»). Можно и командой `/plugin configure ctx@claude-kit` (или `handoff@claude-kit`), так подсказывает сам Claude Code. Посмотреть, какие настройки есть и какие заданы, можно в обычном терминале:

```
claude plugin configure ctx@claude-kit
```

Когда настройка вступает в силу: после сохранения (в `/plugin` или в `/config`) Claude Code сам перезагружает плагины, и новое значение действует сразу. Строка `ctx` при этом меняется без нового сообщения и без перезапуска, в том числе в уже открытых сессиях приложения. Так проверено на настройках `ctx`: в терминале на Claude Code 2.1.309; в приложении 3.1623.4 (его движок — Claude Code 2.1.308) — на смене языка в уже открытой сессии; настройки `handoff` при проверке не менялись, плагин читает их при загрузке так же. Если строка не поменялась, откройте новую сессию.

## Как обновить

В обычном терминале выполните по очереди:

```
claude plugin marketplace update claude-kit
```

```
claude plugin update ctx@claude-kit
```

```
claude plugin update handoff@claude-kit
```

Потом откройте новую сессию: обновление применяется после перезапуска.

## Выключить

В Claude Code откройте `/plugin`, найдите плагин и нажмите Disable (выключить). Тот же результат даёт команда в терминале:

```
claude plugin disable ctx@claude-kit
```

Для `handoff` — то же самое с `handoff@claude-kit`. Включить обратно — `claude plugin enable <плагин>@claude-kit`, убрать совсем — `claude plugin uninstall <плагин>@claude-kit`.

## Что нового

- **ctx 0.3.0:** строка `ctx` стала короче: между частями два пробела вместо трёх, вместо слова «сброс» значок `↻`, у кэша нет значка `◷` (`кэш 2м`). У 5-часового окна появилось время до сброса: `5ч ▪▪▪▪▪▪▫▫ 71% ↻2ч14м`. Новая настройка «Язык строк» (`lang`): `ru` (по умолчанию) или `en`; английской становится вся полоса, включая строку субагентов. Стоимость `$` по умолчанию выключена (на подписке это условная сумма); чтобы вернуть её, включите «Показывать стоимость» (`showCost`), а кто включал её сам раньше, продолжит видеть сумму. После `/clear` сумма считается заново: её считает Claude Code.
- **ctx 0.2.0:** во вкладке Code приложения Claude в нижнем ряду слева от модели появилась папка сессии (две последние части пути, например `CLAUDE/claude-kit`), а в полосе над полем ввода над строкой `ctx` — строка субагентов: `агенты   работают 1   готово 16`, плюс `сбой N`, если кто-то упал или был остановлен. Шкалы остались в полосе над полем ввода. В терминале всё по-прежнему.
- **handoff 0.1.2:** фраза «ок /handoff-now» (или «давай handoff-now») запускает передачу так же, как команда `/handoff-now`; раньше она уходила в Claude обычным текстом и получался ручной хендофф без новой сессии. Ручной хендофф `/handoff:handoff` теперь ложится в папку, где началась сессия, как и автоматический, а не во вложенный репозиторий, куда перешёл Claude.
- **ctx 0.1.1:** во вкладке Code приложения Claude строка `ctx` стоит в полосе над полем ввода. Приложение (с версии 2.37) стало рисовать строку плагина отдельным рядом под выбором модели, а вернуть её в ряд «Auto / Opus» плагин не может. В терминале всё по-прежнему.
- **handoff 0.1.1:** автоматическая передача считает папку проекта по той папке, в которой открыта сессия, а не по той, куда Claude перешёл во время работы (`cd`): хендофф и новая сессия остаются в проекте, где всё началось.

## Известные особенности

1. **Окно Терминала на Mac после закрытия старой сессии.** Когда старая сессия закрылась, а вы вставляете текст в то же окно, в нём может появиться `[200~`. Наберите `reset` и нажмите Enter или откройте новую вкладку.
2. **Где лежат хендоффы.** Claude берёт первую существующую папку из списка: `docs/superpowers/handoffs`, `plans/handoffs`, `docs/handoffs`, `.claude/handoffs`. Если ни одной нет, создаётся `docs/superpowers/handoffs` (когда в проекте есть `docs/superpowers`) или `docs/handoffs`. Проще говоря, в обычном проекте по умолчанию это `docs/handoffs/`. Без Git — `docs/handoffs` в папке, где началась сессия, и без коммита. Папка проекта — та, в которой вы открыли сессию (пока вы сами не сменили проект, например командой `/cd`): если во время работы Claude перешёл (`cd`) в подпапку или во вложенный репозиторий, хендофф всё равно ляжет в проект, где сессия началась (и при автоматической передаче, и при ручной `/handoff:handoff`). Файл автоматической передачи называется `HANDOFF_auto_ГГГГ-ММ-ДД-ЧЧММСС.md`.
3. **Старая папка `.claude/handoffs`.** Если в проекте она уже есть (и нет ни одной из трёх папок, которые стоят в списке выше неё), хендоффы пишутся туда, а Claude Code спрашивает разрешение на каждую запись в папку `.claude/`. Автоматическая передача из-за этого будет ждать вашего щелчка. Совет: переименуйте папку в `docs/handoffs` (можно попросить Claude: «перенеси папку `.claude/handoffs` в `docs/handoffs`»).
4. **Сессия открыта не в Git-репозитории.** Если папка, в которой вы открыли сессию, не находится внутри Git-репозитория (например, это общая папка, а репозитории лежат в ней по отдельности), хендофф сохраняется без коммита. Хотите коммиты — открывайте сессию в папке самого репозитория.
5. **В приложении шкалы — над полем ввода.** Во вкладке Code приложения Claude строка `ctx` стоит в полосе над полем ввода, а не под ним, как в терминале. Нижний ряд приложения (слева от выбора модели) узкий для строки шкал, поэтому в нём стоит только папка сессии, а шкалы вынесены в полосу. Подпись `ctx` в начале полосы ставит сам плагин (у полосы, в отличие от строки состояния, своей подписи нет). Если окно приложения узкое, строка `ctx` не переносится на вторую строку, а обрезается справа многоточием (например, `… ↻…`: место обреза зависит от ширины окна); расширьте окно, чтобы увидеть её целиком. Полосу можно свернуть значком `[-]` рядом с ней. Пока приложение задаёт вам вопрос в этой полосе (опрос), строка `ctx` и строка субагентов уступают ему место.
6. **Строка субагентов считает по списку, который отдаёт Claude Code.** Агентов внутри workflow (скрипта, который сам запускает агентов) Claude Code плагинам не показывает, поэтому в строке их нет. Навык, который Claude Code запускает отдельным потоком, он отдаёт в том же списке, и такой навык считается как субагент. Claude Code убирает агентов из списка уже после конца их работы; агент, который пропал из списка, пока считался работающим, учитывается как `готово`, даже если на деле упал. Так бывает, только если плагин не прочитал агента упавшим после того, как в последний раз видел его работающим: он упал и пропал из списка раньше, чем список перечитали, или чтение, которое его видело, не удалось. Список перечитывается в конце каждого хода агента и раз в минуту. Если два чтения списка шли одновременно, цифры могут на время показать не то состояние агента (например, снова «работает»); следующее чтение это исправляет.
