# claude-kit

Бесплатный набор из двух плагинов для Claude Code. Плагин — это дополнение, которое ставится в Claude Code отдельной командой и расширяет его возможности.

## Что это

- **`ctx`** — строка под полем ввода: сколько занято контекста (это «память» текущего разговора с Claude), какая доля лимитов за 5 часов и за неделю уже использована, сколько минут прошло с последнего ответа Claude (пока кэш «тёплый», следующий ответ обычно дешевле) и сколько стоит сессия по оценке Claude Code.
- **`handoff`** («передача смены») — когда контекст заполняется, работа одной кнопкой переезжает в **новую** сессию того же проекта. Старая сессия остаётся на месте, работа записана в файл и (если в проекте есть Git) сохранена коммитом.

Так выглядит строка `ctx` в терминале:

```
⚠ ctx: ▪▪▪▪▫▫▫▫ 48%   5ч ▪▫▫▫▫▫▫▫ 14%   кэш ◷ 2м   $0.84
```

`⚠ ctx:` в начале — это подпись самого Claude Code (он так подписывает строку любого плагина; в приложении подпись просто `ctx`). Тревогой этот значок не является. Наша строка начинается с первого квадратика. Тревога у нас — значок 🔴 (о нём ниже).

Вживую на Mac (Claude Code 2.1.295) проверены: строка под полем ввода (терминал и вкладка Code приложения Claude), значок 🔴 (терминал), вопрос на пороге (терминал; ответ своим текстом — в приложении), ручной запуск `/handoff:handoff` (терминал) и передача по команде `/handoff-now` (терминал и приложение). Только автоматическими тестами проверены запасной путь с буфером обмена и доводка передачи после перезапуска. На Windows не проверялось ничего (см. раздел «Windows»).

## Что нужно

1. **Claude Code версии 2.1.293 или новее** (проверено на 2.1.293–2.1.296). Версию показывает команда:

```
claude --version
```

На более старой версии шкалы и вопрос о передаче могут не заработать. Тогда остаётся ручная команда `/handoff:handoff` (см. ниже).

2. **Git** (система сохранения версий файлов). Он нужен, чтобы передача могла сохранить работу коммитом (коммит — снимок изменений в Git). Без Git хендофф всё равно запишется, но коммита не будет.
3. **Python 3** — на нём работают служебные скрипты передачи.
   - Mac: Python обычно уже есть, а если нет, macOS предложит поставить «Xcode Command Line Tools» — согласитесь.
   - Windows: скачайте с python.org и при установке поставьте галочку «Add to PATH» (в окне установщика она называется что-то вроде «Add python.exe to PATH»).
   - Если Python на компьютере нет совсем, скилл переключается на запасной путь: те же шаги через команды Git. Но этих команд (в том числе `git add` и `git commit`) нет в списке заранее разрешённых, поэтому в обычном режиме разрешений Claude Code может спросить у вас разрешение, и автоматическая передача будет ждать вашего щелчка. Так что Python лучше поставить.

## Установка

Откройте обычный терминал (не внутри Claude): на Mac это приложение «Терминал», на Windows — PowerShell или Windows Terminal. Выполните по очереди три команды.

Добавить каталог (список плагинов этого набора):

```
claude plugin marketplace add bonosurgut/claude-kit
```

Поставить `ctx`:

```
claude plugin install ctx@claude-kit
```

Поставить `handoff`:

```
claude plugin install handoff@claude-kit
```

Потом **откройте новую сессию** (закройте текущий `claude` и запустите заново; в приложении откройте новый чат). Проверить, что плагины стоят и включены, можно командой:

```
claude plugin list
```

В списке должны быть `ctx@claude-kit` и `handoff@claude-kit` со статусом «enabled».

Если раньше вы ставили другие моды, которые тоже рисуют строку под полем ввода (например, другой плагин с именем `ctx`), выключите их: набор проверялся без них.

## Как пользоваться

### Шкалы под полем ввода

Строка обновляется после каждого ответа Claude и раз в минуту. В приложении она появляется только после первого ответа Claude в чате.

| Что в строке | Что значит |
|---|---|
| `▪▪▪▪▫▫▫▫ 48%` | Сколько контекста занято. Восемь делений, процент рядом. |
| `5ч ▪▫▫▫▫▫▫▫ 14%` | Сколько использовано из лимита за 5 часов. |
| `нед ▪▪▪▪▫▫▫▫ 48% · сброс чт 10:00` | Сколько использовано из недельного лимита и когда он сбросится (день недели и время — в вашем часовом поясе). |
| `кэш ◷ 2м` | Сколько минут прошло с последнего ответа Claude. Claude Code на несколько минут запоминает уже отправленную часть разговора (это и есть кэш), и пока кэш «тёплый», следующий ответ обычно дешевле. |
| `кэш остыл` | Прошло пять минут или больше: запоминание закончилось. Пять минут — наше предположение по умолчанию. Claude Code может хранить кэш и дольше (например, час); тогда увеличьте «Срок кэша» в настройках. |
| `$0.84` | Сколько стоит эта сессия по оценке Claude Code (считается по прайс-листу API). Если вы работаете по подписке, это справочная цифра, а не сумма, которую с вас спишут. Можно выключить в настройках. |

Если Claude Code не сообщает лимиты (так бывает при работе по API-ключу или через прокси), строки про 5 часов и неделю просто не рисуются. Нулей вместо них не будет. До первого ответа не рисуется кэш, без данных о стоимости не рисуется `$`.

Когда контекст дошёл до 50% (порог можно поменять), в начале нашей строки появляется 🔴:

```
⚠ ctx: 🔴 ▪▪▪▪▪▫▫▫ 62%   5ч ▪▫▫▫▫▫▫▫ 14%   кэш ◷ 2м   $0.84
```

🔴 относится только к контексту: лимиты его не включают.

### Вопрос на 50%

Когда контекст дошёл до 50% (порог можно поменять), на экране появляется вопрос:

> Контекст 50%. Передать работу в новую сессию?

В окне вопроса две кнопки, **«Передать»** и **«Не сейчас»**, и поле «Other» для своего текста. Отвечайте кнопками: любой текст, который вы впишете в поле (например, «да»), считается ответом «Не сейчас», и передача не начнётся.

- «Передать» запускает передачу (что она делает — ниже).
- «Не сейчас» (а также свой текст в поле или закрытый вопрос) — вопрос повторится, когда контекст вырастет ещё на 10 процентных пунктов (шаг можно поменять) от того значения, при котором вас спросили. Спросили на 50% — повторят на 60%, потом на 70% и так далее.
- Пока идёт передача, вопроса нет. Если передача дошла до открытия новой сессии (или до запасного пути с буфером обмена, см. ниже), вопрос молчит, пока контекст не упадёт ниже порога. Если передачу отменили (сообщения «… — ничего не закрыто», см. ниже), вопрос включается снова и появится так же, как обычно, когда контекст достигнет порога (если контекст уже выше, то при ближайшем обновлении процента).

### Команда `/handoff-now`

Не хотите ждать 50%? Напишите в поле ввода `/handoff-now`, и передача начнётся сразу, при любом проценте контекста. В ответ появится сообщение «Пишу хендофф; потом коммит и новая сессия». Если передача уже идёт, вместо этого будет «Передача уже идёт: <путь к файлу>», и вторая не начнётся.

### Что делает «Передать»

Хендофф — это файл-пересказ работы: какая цель, что уже сделано, что пробовали (в том числе неудачное) и что делать дальше.

1. Claude пишет хендофф в папку проекта (по умолчанию `docs/handoffs/`, подробности — в разделе «Известные особенности»).
2. Коммит. В него попадают: сам хендофф, оглавление хендоффов `INDEX.md` и файлы, которые Claude создал или менял в этой сессии. Остальные изменения в папке (например, ваши правки руками) в коммит не попадают. **Файлы с «секретными» именами в коммит не попадают**, даже если их нет в `.gitignore`: `.env*`, `*.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.keystore`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `id_dsa*`, а также файлы со словами `secret` и `credentials` в имени и файлы в папках с такими именами. Проверяется только имя, содержимое файлов не читается: пароль внутри файла с обычным именем эта защита не заметит. Пропущенные файлы Claude перечисляет в своём отчёте. Если коммит не прошёл (нет Git, коммит отклонила проверка и т. п.), передача всё равно идёт дальше, а Claude записывает причину в хендофф.
3. Открывается новая сессия того же проекта:
   - **Терминал (Mac):** новое окно Терминала. Старая сессия закрывается последним шагом, и только после того, как новое окно открылось. Окно с ней остаётся, а саму сессию можно вернуть командой `claude --resume`.
   - **Приложение Claude (вкладка Code):** в списке появляется новый чат с пересказом. Старый чат остаётся в списке как есть, он не закрывается и не архивируется.
4. Новая сессия читает хендофф, пересказывает его в 5–8 строках (цель, состояние, что пробовали и что не вышло), читает только самые нужные файлы, говорит, что проверит первым, и **ждёт, пока вы напишете «поехали»**. После этого она продолжает работу с раздела хендоффа «Where We're Going» (план следующих шагов).

Передача занимает время: сначала Claude пишет хендофф и коммитит, и только потом открывается новая сессия. Если файла хендоффа нет через 15 минут, передача отменяется, а старая сессия работает дальше.

### Если что-то пошло не так

В терминале старая сессия закрывается только после того, как новая успешно открылась (в приложении старый чат не закрывается вообще). Если что-то не получилось, вы увидите сообщение (оно показывается несколько секунд). Вот основные из них:

| Сообщение | Что случилось |
|---|---|
| «Хендофф не запустился (причина) — ничего не закрыто» | Передачу не удалось начать: например, хранилище не приняло служебную метку или не запустился сам скилл `handoff:handoff`. Старая сессия работает. |
| «Хендофф не записан — ничего не закрыто» | Claude закончил ход, а файла хендоффа нет. Старая сессия работает, можно повторить. |
| «Хендофф не дождались — ничего не закрыто» | Файла нет уже 15 минут. Старая сессия работает. |
| «Передача остановлена — ничего не закрыто» | Вы прервали Claude, пока он писал хендофф. |
| «Новая сессия не открылась сама (причина). Фраза скопирована: …» | Окно или чат не открылись. Фраза для новой сессии лежит в буфере обмена, а конец сообщения подсказывает, что делать дальше (три варианта ниже). **Старая сессия при этом не закрывается.** |
| «Новая сессия открыта, но закрыть эту не вышло (причина)» | Новое окно терминала открылось, а команда закрытия старой сессии не сработала. Старая сессия осталась открытой: закройте её сами командой `/exit`. |

Что делать с сообщением про скопированную фразу, смотрите по тому, чем оно заканчивается. Конец зависит от того, где идёт ваша сессия:

- в приложении («…нажми ⌘N и вставь»; на Windows `Ctrl+N`): нажмите это сочетание, чтобы открыть новый чат, и вставьте фразу;
- в терминале («…открой новое окно терминала, запусти claude в папке проекта и вставь»): откройте новое окно или вкладку, запустите в папке проекта `claude` и вставьте фразу;
- в остальных местах, например в расширении для VS Code («…открой новую сессию Claude Code в папке проекта и вставь»): откройте новую сессию Claude Code в папке проекта и вставьте фразу.

Сочетание `⌘N` в сообщении называется только для приложения: в Терминале оно по умолчанию открывает новое окно с обычной оболочкой, а в VS Code — новый пустой файл.

Если буфер обмена недоступен, фраза целиком показывается прямо в сообщении (подсказка в нём та же, но с большой буквы и с двоеточием перед фразой). Кроме того, в этом случае фраза дописывается одной строкой в историю чата: сообщение исчезает через несколько секунд, а запись в истории остаётся.

Новая сессия сама открывается только в терминале и во вкладке Code приложения. В других местах (например, в расширении для VS Code) вы получите это сообщение с фразой в буфере и подсказкой открыть новую сессию самому.

### Ручной режим `/handoff:handoff`

Запасной способ, если вопрос на пороге не появляется (например, на старой версии Claude Code): набрать `/handoff:handoff`. Claude так же пишет хендофф и коммитит без секретов, но новую сессию сам не открывает и старую не закрывает. В конце он печатает фразу, которую вы вставляете в новую сессию сами, и подсказывает, как её открыть.

## Рекомендуемая настройка: режим Auto

Режим разрешений **Auto** (автоматический) означает: Claude сам решает, какие действия безопасны, и выполняет их, не спрашивая вас каждый раз. Рискованные действия по-прежнему требуют вашего «да». Риск в одну строку: решение «безопасно или нет» принимает сама модель, и она может ошибиться.

Зачем это нужно: пока в настройках не задан режим по умолчанию, приложение открывает любой новый чат в режиме **Manual** (каждое действие спрашивает разрешение), в том числе чат, который открыла передача. Переключить его можно одним щелчком в самом чате, но проще один раз задать режим по умолчанию.

Как включить: вставьте Claude эту фразу.

```
Пропиши в `~/.claude/settings.json` режим разрешений по умолчанию `auto` (`permissions.defaultMode`)
```

Claude попросит разрешение изменить файл настроек, вы соглашаетесь. После этого и обычные новые чаты, и чат, открытый передачей, стартуют в Auto. Сами плагины настройки Claude Code никогда не меняют.

Если Claude Code не принял значение `auto` (режим может быть недоступен на вашем тарифе), оставьте как есть: всё остальное работает, только новый чат в приложении придётся один раз переключить вручную. Чтобы вернуть всё назад, попросите Claude убрать эту настройку.

## Настройки

| Плагин | Настройка | Что делает | По умолчанию |
|---|---|---|---|
| `handoff` | Порог вопроса, % (`threshold`) | С какого процента контекста спросить «Передать?» | 50 |
| `handoff` | Повторить через, % (`step`) | На сколько процентных пунктов должен вырасти контекст после «Не сейчас», чтобы вопрос повторился | 10 |
| `ctx` | Предупреждение 🔴 с, % (`redAt`) | С какого процента контекста перед шкалой ставится 🔴 | 50 |
| `ctx` | Срок кэша, мин (`cacheMinutes`) | Через сколько минут после ответа Claude кэш считается остывшим (по умолчанию считаем, что кэш живёт 5 минут) | 5 |
| `ctx` | Показывать стоимость (`showCost`) | Показывать ли `$` в строке | да |

Порог вопроса держится в пределах от 1 до 100, а шаг — целое число не меньше 1; значения вне этих границ программа поправит сама. По умолчанию порог вопроса и порог 🔴 совпадают (оба 50), и оба сравнивают процент, округлённый до целого, то есть тот, что вы видите в строке. Поэтому 🔴 и вопрос появляются на одном и том же проценте (вопроса может не быть, если вы уже ответили «Не сейчас» и он ждёт следующего порога или если передача уже идёт). Если захотите разнести пороги, меняйте каждый отдельно.

Где поменять: в Claude Code откройте `/plugin` → Installed → нужный плагин → настройки. Можно и командой `/plugin configure ctx@claude-kit` (или `handoff@claude-kit`), так подсказывает сам Claude Code. Посмотреть, какие настройки есть и какие заданы, можно в обычном терминале:

```
claude plugin configure ctx@claude-kit
```

После изменения откройте новую сессию, чтобы настройки точно подхватились.

## Как обновить

В обычном терминале выполните по очереди:

```
claude plugin marketplace update claude-kit
```

```
claude plugin update ctx@claude-kit
```

```
claude plugin update handoff@claude-kit
```

Потом откройте новую сессию: обновление применяется после перезапуска.

## Выключить

В Claude Code откройте `/plugin`, найдите плагин и нажмите Disable (выключить). Тот же результат даёт команда в терминале:

```
claude plugin disable ctx@claude-kit
```

Для `handoff` — то же самое с `handoff@claude-kit`. Включить обратно — `claude plugin enable <плагин>@claude-kit`, убрать совсем — `claude plugin uninstall <плагин>@claude-kit`.

## Известные особенности

1. **Окно Терминала на Mac после закрытия старой сессии.** Когда старая сессия закрылась, а вы вставляете текст в то же окно, в нём может появиться `[200~`. Наберите `reset` и нажмите Enter или откройте новую вкладку.
2. **Где лежат хендоффы.** Claude берёт первую существующую папку из списка: `docs/superpowers/handoffs`, `plans/handoffs`, `docs/handoffs`, `.claude/handoffs`. Если ни одной нет, создаётся `docs/superpowers/handoffs` (когда в проекте есть `docs/superpowers`) или `docs/handoffs`. Проще говоря, в обычном проекте по умолчанию это `docs/handoffs/`. Без Git — `docs/handoffs` в текущей папке и без коммита. Файл автоматической передачи называется `HANDOFF_auto_ГГГГ-ММ-ДД-ЧЧММСС.md`.
3. **Старая папка `.claude/handoffs`.** Если в проекте она уже есть (и нет ни одной из трёх папок, которые стоят в списке выше неё), хендоффы пишутся туда, а Claude Code спрашивает разрешение на каждую запись в папку `.claude/`. Автоматическая передача из-за этого будет ждать вашего щелчка. Совет: переименуйте папку в `docs/handoffs` (можно попросить Claude: «перенеси папку `.claude/handoffs` в `docs/handoffs`»).

## Windows

**Не проверено вживую.** У автора нет компьютера с Windows, поэтому ни строка, ни передача на нём не запускались. Код для Windows написан и покрыт автоматическими тестами (они проверяют, какие команды будут запущены), но самих окон никто не видел.

Если что-то не так — пройдите [`docs/windows-checklist.md`](docs/windows-checklist.md) и напишите автору.

## Для автора

- **Перед каждой публикацией поднимайте `version`** в обоих файлах: `plugins/ctx/.claude-plugin/plugin.json` и `plugins/handoff/.claude-plugin/plugin.json`. Пока номер версии прежний, `claude plugin update` у клиентов ничего не подтягивает (это выяснилось при живой проверке 2026-10-10, см. [`docs/live-check.md`](docs/live-check.md)).
- Проверки перед публикацией (запускать из корня репозитория; pytest стоит в локальной папке `.venv`, она не коммитится):

```
claude plugin validate .
```

```
claude plugin validate plugins/ctx
```

```
claude plugin validate plugins/handoff
```

```
claude plugin test plugins/ctx
```

```
claude plugin test plugins/handoff
```

```
.venv/bin/python -m pytest plugins/handoff/tests -q
```

- Какая фича чем проверена — [`docs/traceability.md`](docs/traceability.md). Результаты живой проверки на Mac — [`docs/live-check.md`](docs/live-check.md). Спецификация — [`docs/superpowers/specs/2026-10-08-claude-kit-design.md`](docs/superpowers/specs/2026-10-08-claude-kit-design.md).
